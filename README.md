## 项目介绍

《**侨缘信使**》是一个旨在宣传和传承侨批文化的互动网站。文化内容的数字化呈现、互动性与教育性的结合、情感共鸣的构建以及用户参与的文化共创。我们致力于通过网站，让更多人了解并参与到侨批文化的保护与传承中来，同时为文化带来新的活力。学习侨批文化、体验写侨批、收侨批和漂流瓶等功能，感受慢信文化的魅力，"跨越四海，侨缘线牵——侨缘信使，让世界没有距离。"

平台还引入了智能交互能力作为支撑，使 AI 能够在不同文化语境下参与用户的创作与交流，在情感引导、文化背景补充与内容辅助等方面提供恰当支持，提升整体互动的连贯性与沉浸感。同时，该能力也被应用于平台的管理端，用于辅助内容整理与日常运营，让使平台在保持文化温度的同时更加高效、灵活。
<p align = "right">—— 五灵威力小队</p>

**v1.0.0 技术栈**

- **前端**：JavaScript、Vue 2、Vue Router、Pinia、Vuex、Element UI、AVue、Canvas API、Axios、Less、Vue CLI、Webpack、ESLint
- **后端**：Java 17、Spring Boot 3、MyBatis-Plus、MySQL、Redis、RabbitMQ、MinIO、JWT、Knife4j、Maven

## 快速部署

> 本仓库同时保留可运行的 v1、独立的 Agent 智能中台，以及正在初始化的 v2。请先确认目标模块，再按需启动；无需一次运行全部服务。

### 模块状态

| 目录 | 定位 | 当前状态 |
|---|---|---|
| `qio-frontend/` | v1 用户前端 | 可运行 |
| `qio-backend/` | v1 业务后端 | 可运行 |
| `qio-agent-service/` | Agent 运行时与管理 API | 可编译、可运行 |
| `qio-agent-console/` | Agent 内部配置与运营控制台 | 可运行、可构建 |
| `qio-frontend-v2/` | v2 用户前端 | 占位，尚未初始化 |
| `qio-backend-v2/` | v2 业务后端 | 占位，尚未初始化 |

### 环境准备

根据需要运行的模块准备以下环境：

- Git
- Node.js 与 npm
- Java 17
- Maven 3.6+
- MySQL
- Redis
- RabbitMQ（v1 业务后端）
- MinIO（v1 业务后端）
- PostgreSQL 与 pgvector（Agent RAG）

只体验部分功能时，可以仅启动对应模块及其必要依赖。

### 获取项目

```bash
git clone git@github.com:Chuppch/Qio.git
cd Qio
```

### 启动 v1 用户产品

#### 1. 启动业务后端

启动前，请先检查 `qio-backend/Qiaopi-server/src/main/resources/application-dev.yml`，配置本地 MySQL、Redis、RabbitMQ、MinIO、邮件和第三方服务。不要把真实密钥或生产连接信息提交到仓库。

```bash
cd qio-backend
mvn -pl Qiaopi-server -am spring-boot:run
```

当前业务后端默认端口为 `3031`。

#### 2. 启动用户前端

```bash
cd qio-frontend
npm install
npm run serve
```

开发服务器默认运行在 `http://localhost:3010`。前端通过 `/api` 访问业务后端，启动前需要确认 `qio-frontend/vue.config.js` 中的代理地址与实际后端端口一致。

> v1 部分 WebSocket 地址仍直接写在页面源码中，并可能指向 `localhost:8080`。本地联调时需要与当前业务后端地址保持一致；后续应统一迁移为环境变量配置。

### 启动 Agent 智能中台

Agent 中台为侨缘信使提供写信辅助、文化知识问答、RAG 检索、多语言处理和工具调用能力。普通用户不应直接访问 Agent Console。

#### 1. 配置并启动 Agent Service

开发配置位于：

```text
qio-agent-service/qio-agent-app/src/main/resources/application-dev.yml
```

配置支持以下环境变量：

| 环境变量 | 用途 |
|---|---|
| `QIO_MYSQL_URL` | Agent 业务数据库地址 |
| `QIO_MYSQL_USERNAME` | MySQL 用户名 |
| `QIO_MYSQL_PASSWORD` | MySQL 密码 |
| `QIO_PGVECTOR_URL` | PostgreSQL/pgvector 地址 |
| `QIO_PGVECTOR_USERNAME` | PostgreSQL 用户名 |
| `QIO_PGVECTOR_PASSWORD` | PostgreSQL 密码 |
| `QIO_REDIS_HOST` | Redis 地址 |
| `QIO_REDIS_PORT` | Redis 端口 |
| `QIO_REDIS_PASSWORD` | Redis 密码 |
| `QIO_OPENAI_BASE_URL` | OpenAI 兼容模型接口地址 |
| `QIO_OPENAI_API_KEY` | 模型服务密钥 |

编译并启动：

```bash
cd qio-agent-service
mvn package -DskipTests
mvn -pl qio-agent-app -am spring-boot:run
```

Agent Service 默认运行在 `http://localhost:8091`。

#### 2. 启动 Agent Console

```bash
cd qio-agent-console
npm install
npm run dev
```

注意事项：

- Agent Console 是内部管理工具，不应直接暴露到公网。
- 当前 API 地址集中在 `qio-agent-console/src/config/api.ts`，本地运行时应指向 Agent Service。
- 当前 `npm run build` 仍是占位脚本；需要验证真实构建时使用 `npx rsbuild build`。
- 当前 lint 仍包含上游遗留问题，不能把 `npm run lint` 失败直接视为本次改动引入的回归。

### v2 当前状态

`qio-frontend-v2/` 与 `qio-backend-v2/` 目前只用于标记下一代架构边界，尚未初始化应用代码，暂时没有可执行的启动命令。

规划中的技术方向为：

- 用户前端：Next.js、React、TypeScript
- 业务后端：Go、Gin
- Agent Service：继续作为独立 Java 服务演进

### 最小验证命令

| 模块 | 建议命令 |
|---|---|
| v1 前端 | `npm run lint`、`npm run build` |
| v1 后端 | `mvn package -DskipTests` |
| Agent Service | `mvn package -DskipTests` |
| Agent Console | `npm run lint`、`npx rsbuild build` |

执行验证时，请结合上文所述的既有 lint 状态和外部基础设施依赖判断结果。

### 安全注意事项

- 不要提交数据库密码、模型 API Key、地图 Key、邮件授权码或服务器地址。
- 不要在浏览器端保存只能由服务端使用的密钥。
- 私人信件、用户身份、收件地址和完整 Prompt 不应写入普通运行日志。
- Agent 能力应由 Qio 业务后端统一鉴权、限流和审计，用户前端原则上不直接调用 Agent Service。
- Agent Console 应部署在内网或受控访问环境。
- 生产环境必须使用 HTTPS，并通过环境变量或专用密钥服务注入敏感配置。

### 生产部署边界

推荐的外部访问关系如下：

```text
Internet
   |
   v
Nginx / Gateway
   |-- /        -> Qio 用户前端
   |-- /api/    -> Qio 业务后端
   `-- /ws/     -> Qio WebSocket 服务

Qio 业务后端
   `-- 内部调用 -> Qio Agent Service

受控管理网络
   `-- Qio Agent Console -> Qio Agent Service
```

根 README 不再维护绑定特定服务器地址的完整 Nginx 配置。后续生产部署方案将统一整理到 `docs/deployment/`，并按环境管理域名、证书、反向代理、容器编排和数据持久化配置。
